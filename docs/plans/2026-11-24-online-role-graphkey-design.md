# 在线登录角色选择与图形验证码设计

## 背景与目标

当前 `--online` 已能进行账号认证，但启动时要求手填角色名和“角色代码”，并在收到角色记录前发送 `0x1002`，导致认证后无法重定向。真实流量和静态证据确认：`0x1002` 携带所选角色名与 `graphkey.scp` 的图形验证码输入，角色 ID 不能代替图形验证码。

目标是在复刻客户端内独立完成账号登录、角色选择和图形验证码输入，再进入既有限定在线聊天模式。范围仍只有登录与聊天，不包含移动、NPC 同步或完整世界状态。

## 已确认证据

- 原版账号认证后收到 `0x2000`：本账号样本为 147B payload，包含一个 0x85B 角色记录；角色 ID 位于 payload `+0x0e`，角色名位于 `+0x12`。实现必须支持累计多个 `0x2000` 角色记录，不假定只有一个角色。
- 原版时序为账号认证与角色记录 → 用户选择角色 → `0x100b` → `0x2005` → 用户输入图形验证码 → `0x1002` → `0x2002`。
- `0x1002` payload 为 41B：`+0x0e` 为角色名，`+0x22` 为最多 7B 的图形验证码输入。`FUN_00525750` 对应 `config/ui/login/graphkey.scp`，并设置 7 字符输入上限。
- 图形验证码随登录会话变化，不能从角色 ID、旧抓包或固定常量生成。
- `0x2005` 的图片载荷格式/混淆解码仍需实现前闭合；不得用“配置大块”的标签代替图片解码证据。
- 已定位并修复接收层的两个超时问题：成功读取长度头未计入进度，以及部分帧超时错误被当作空闲轮询。后台单帧接收期限由 20ms 调整为有界 1 秒，30 秒认证总期限保持不变。

## 方案

采用协议状态机与两个简单 Win32 对话框，不直接把整套 SCP/Lua 登录界面嵌入网络核心。

### 初次账号输入

初次对话框只接收账号、密码、区服、版本和动态畅游码。删除角色名和角色代码手填项，避免把角色 ID 误作验证码。凭据继续只存在于进程内存，不写命令行、凭据文件或日志。

### 角色选择

`GameSession` 启动时只发送 `0x1005`、`0x1000`、`0x1500`，不再提前发送 `0x100b/0x1002`。收到 `0x2000` 后解析角色记录并累计角色列表。worker 向 UI 发送只含角色显示所需字段的事件，主线程展示角色名和角色 ID，由用户明确选择；没有有效角色时继续等待直至认证期限到期，不自动虚构角色。

用户确认角色后，UI 将角色索引/标识通过有界队列交给 worker，worker 再发送 `0x100b`。角色列表后续如有新增记录，只更新对话框数据，不替换用户已确认的选择。

### 图形验证码

收到角色选择后的 `0x2005` 时，先按实证算法解码图片。worker 向 UI 发送解码后的像素和尺寸，不发送凭据或其他网关载荷。主线程以 Win32 对话框显示图片并提供最多 7 字符的输入框；用户确认后，worker 使用已选角色名和本次输入构造 `0x1002`。

图片解码失败、记录格式异常、空输入或包含非预期字符时明确失败或要求重新输入，不跳过验证。收到 `0x2002` 后才沿用现有游戏服连接、初始化和聊天路径。

## 线程与生命周期

- socket、`GameSession` 和 wire 编解码仍只由 `OnlineChatWorker` 后台线程拥有。
- 角色列表、图片展示、输入和 `ChatModel` 更新只由 UI 主线程执行。
- UI 与 worker 之间的角色选择、图形码输入、状态和错误事件使用现有有界队列模式；文本日志不记录图形码、动态畅游码或聊天正文。
- 对话框取消、认证失败、超时和窗口退出均停止并 join worker，不回退 replay，不伪造登录成功。

## 实施顺序

1. 闭合 `0x2000` 多角色记录与 `0x2005` 图片解码，用脱敏 golden 测试验证字段、像素和异常边界。
2. 调整 `GameSession` 时序及角色/图形码交互 API，保留现有 loopback 登录覆盖。
3. 修改 App/Win32 对话框，完成角色选择和图片输入。
4. 运行 Debug/Release 网络、凭据、聊天和 UI 回归，再做真实双客户端验收。

## 验收

- 单元/loopback 测试覆盖多角色、选择后发 `0x100b`、图片输入后才发 `0x1002`、取消与超时、异常图片和错误重定向边界。
- 真实验收由用户在复刻端完成账号输入、角色选择和图形码输入；确认 `0x2002` 和游戏服会话建立。
- 使用第二个原客户端验证世界与当前频道的唯一测试消息双向收发，日志不泄露凭据或正文。
