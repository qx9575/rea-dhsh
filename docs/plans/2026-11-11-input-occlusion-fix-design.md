# 输入冲突与地图遮挡修正设计

日期：2026-11-11

> 更正（2026-11-11 晚）：本文的 “RGB565 暗化、alpha 不变” 结论有误；
> 原版 ApplyMask 修改的是精灵 alpha 通道，等价于逐字节 `alpha >> 3`
> （255→31），RGB 不变。详见 `docs/VERIFY-INPUT-OCCLUSION.md` 文末更正与
> `docs/formats/map.md` §4.7。以下内容保留为当时的设计记录。

## 背景与证据

用户反馈两个应天府原生客户端问题：左键点击移动与左键拖动相机互相干扰；角色被树木、建筑遮挡时显示为错误的黑色轮廓。`pic/mapdeep.png` 左侧为当前客户端，右侧为原版参照。

输入根因位于 `client/src/input/MapInput.cpp` 与 `client/src/app/App.cpp`：同一个左键按下/移动同时驱动点击候选和相机拖动，拖动关闭跟随，而后续有效点击立即恢复居中跟随。角色寻路本身不需要被拖动中断。

遮挡根因位于 `client/src/scene/CoverMask.cpp`：当前实现逐 RGBA 字节执行 `>>3`。旧基线 `Game.exe` 的 `ApplyMask` 辅助函数 `0x4264b0` 实际对打包的 16 位像素执行 `psraw 3`，再按每个 16 位字应用 `0x1f1f`；常量 `0xaa9e68` 的字节已复核。两种算法不等价，不能通过调整透明度替代。

运行中的 1.50.27 原版只作为视觉参照。其地址已经变化，不把旧基线 VA 用于新版内存读取；不注入、不修改游戏或原 PAK。

## 已确认行为

- 左键只负责点击寻路，不再拖动地图。
- 右键按住才拖动地图；右键按下、移动和松开均不产生寻路目标。
- 右键拖动时角色沿原路径继续移动，相机跟随暂时挂起。
- 右键松开或输入取消时结束拖动，保持当前相机位置，不立即回中。
- 下一次有效左键寻路恢复相机跟随，但按帧平滑接近角色中心，不瞬时跳转。
- UI 命中的按下不启动地图手势；右键拖动优先于拖动期间的左键点击。
- 保留现有 core 地线深度、RLE 覆盖范围、MAN 排序和角色 alpha，不增加统一透明或重画遮挡物。

## 实现结构

### Win32 事件与捕获

在 `WindowEvent` 增加右键按下/松开事件，分别映射 `WM_RBUTTONDOWN`/`WM_RBUTTONUP`。窗口对左右键维护捕获状态；只有所有已捕获按键都释放后才调用 `ReleaseCapture`。`WM_CAPTURECHANGED` 和 `WM_KILLFOCUS` 继续生成统一的 `input_cancelled`。

### 地图手势与相机

`MapInput` 分别保存左键点击候选和右键拖动状态，提供明确的 `camera_dragging()` 查询。`InputState` 只保留键盘平移状态，避免再维护一份重复的鼠标拖动状态。

右键在地图区域按下时，以当前相机和缩放记录地图锚点。鼠标移动时使用固定锚点计算相机位置，再按地图边界截断。右键松开只结束手势，不改相机坐标。

有效新路径启用跟随。跟随目标仍为角色位于逻辑视口中心；每个渲染帧使用基于真实帧时间的指数趋近：

```text
weight = 1 - exp(-elapsed_ms / 120)
camera += (target - camera) * weight
```

零时间步不改变相机；足够接近目标时收敛到目标，避免长期无效重绘。相机目标与当前值均执行既有边界截断。键盘和滚轮行为保持现状。

### core 遮挡像素

保留 `CoverMask::apply` 的公开接口和缓存结构。对掩码覆盖且实际参与合成的角色像素：

1. 将 RGB 就近量化到 RGB565；
2. 以 16 位有符号字执行算术右移 3 位；
3. 应用 `0x1f1f`；
4. 使用项目现有 5/6 位到 8 位换算转回 RGB；
5. 原样保留 alpha。

该转换只替换当前错误的逐通道暗化，不修改深度条件、遮挡候选缓存或透明像素合成规则。

## 测试与验收

先写并运行失败测试，再修改实现：

- 左键拖动不再改变相机，简单左键仍只产生一个正确地图目标；
- 右键拖动不产生目标，按下/移动/松开和输入取消正确管理状态；
- UI 命中、黑边、左右键交错和捕获释放不会遗留手势；
- 右键拖动固定锚点，角色继续移动，松开不跳变；
- 恢复跟随的第一帧位于旧相机与目标之间，连续帧最终收敛；
- 多组 RGBA 像素与独立 RGB565 参考计算一致，覆盖/未覆盖和 alpha 行为不变；
- 更新原来明确断言逐通道 `>>3` 的测试，使其断言已确认的原版 16 位算法，而不是保留错误输出。

最终运行完整 Win32 Release CTest，并执行真实窗口回归：点击长距离移动、移动中右键拖动、松开、再次点击，确认无寻路冲突和相机瞬跳；在 `mapdeep.png` 对应树木/柱子场景对比遮挡颜色、alpha、深度及性能统计。完整游戏联机行为不在本次范围内。
