# kimi_viewer 职业联动与模型映射设计

## 目标

修正人物职业联动、装备职业过滤和装备动画；移除坐骑类别的技能控件；补全可验证的模型 ID 与名称对照。所有模型保持可浏览，无法证明正式名称的模型标为“待确认”，不编造名称。

## 方案

采用静态资源表优先、运行时内存定向补充的方式。静态表提供可复现映射；只有运行时对象能同时关联资源 ID 和名称时才接受内存结果，并记录证据和覆盖缺口。

## 界面与数据流

### 人物

职业、进阶、性别变化后重新生成装备和坐骑选项。装备可用范围来自 `itemSpecData.csv` 的职业权限及实际存在的模型资源，而不是 `viewjob.csv` 的默认套装。身体和头部不套用物品职业权限。坐骑范围来自职业、进阶、性别、坐骑资源之间的已验证关系。旧选择仍有效时保留，否则选择首个有效项并刷新画面。

### 装备

职业过滤按物品职业标志执行。修复 CSV 解码，统一名称和职业字段。可装配物品根据槽位换算模型 ID，并加载对应部位 APG 动画；没有模型的物品继续显示图标和详情，明确标注无模型动画。修复左右护腕目录大小写造成的枚举缺失。

### 坐骑

隐藏技能、光效和变体控件，仅保留坐骑、骑甲、动作、方向、染色和资源明细。骑甲按坐骑关系过滤，并接入物品名称映射。

### 映射层

统一返回名称列表、来源和确认状态，避免重复 ID 被单值字典静默覆盖。显示格式为 `名称(ID)` 或 `待确认(ID)`。映射来源包括物品表、怪物表、音效表、NPC 头像表、坐骑表与职业预设交叉关系、`bodyidequal.csv` 别名，以及经核验的运行时证据。

废弃“坐骑模型 ID = 怪物 ID−30800”的通用假设。坐骑优先使用 `horseinfo.csv` 与 `viewjob.csv` 的职业、进阶、性别和资源 ID 交叉关系。物品模型公式仅用于已验证的装备槽位，并要求目标资源实际存在。

## 验证与文档

先写会失败的离屏测试，分别复现职业过滤、人物装备联动、装备动画、坐骑技能隐藏、护腕枚举和名称映射问题，再做最小修复。验证所有类别切换及既有技能切换不回归，随后进行真实窗口检查。

生成已确认与待确认覆盖清单。静态表无法解决且运行时可观察的缺口，再逐类进行内存对照；无法形成证据链的保留待确认。完成后同步 README、优化文档和 PROGRESS，并提交代码、测试和文档。
