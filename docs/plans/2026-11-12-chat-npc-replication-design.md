# 聊天、NPC 与右侧 UI 复刻设计

- 日期：2026-11-12
- 状态：已与需求方分三部分确认
- 前置交接：`docs/plans/2026-11-12-chat-npc-replication-handoff.md`
- 路线：公共协议/SCP 底座 + NPC、聊天、右侧面板三条垂直验收线

## 1. 目标与边界

复用旧版 PAK、SCP、Lua、CSV、图像和动画，通过静态与只读动态分析补齐
Hero2D 的原生行为。本轮不继续手工拼近似 UI，也不以运行时提示表猜测 NPC
模型。

已确认的验收边界：

1. 协议优先，先以真实抓包回放驱动 C++ 客户端，再接实网登录和同步。
2. NPC 使用通用的“网络对象 -> 场景实体”数据流，不扩大硬编码提示表。
3. 独立聊天窗恢复原 SCP、皮肤、消息、输入和通用交互。
4. 右侧按钮必须打开对应的真实 SCP/Lua 面板，支持打开、关闭、切换、滚动和
   空数据状态；本轮不要求把所有业务协议一次做完。
5. 离线无数据时显示真实空面板，不伪造 NPC、聊天、任务、排行或活动结果。

## 2. 已确认的新证据

### 2.1 NPC 配置与网络

- `config.pak:npc.csv` 与 `config.pak:misc/npc.csv` 都是 NPC 搜索/坐标表，
  列语义为 NPCID、名称、地图、格子、显示分类等，不包含通用 shape 映射。
- `config.pak:monster/npchead.csv` 只有 8 行特殊“头像 ID -> 实体 ID/索引色”
  映射，不能承担世界 NPC 名单或通用模型解析。
- `config.pak:misc/npcdlg.csv` 是编号对话文本与按钮配置；
  `config.pak:mapnpclink.csv` 是 NPC 地图跳转配置。它们补充交互，不提供
  当前地图实例和模型。
- 运行时对象中的 shape、像素位置和方向由服务器动态下发；只读扫描是当前
  实例的证据，不应编译成通用名单。
- 现有 Python 工具已经能离线解密游戏消息。已标注 `0x303f` 聊天广播、
  `0x4050` 聊天发送、`0x301e/0x301f/0x30a0/0x300d` 对象同步候选消息；
  具体 NPC 字段仍须与对象和截图对齐后确认。
- 当前 C++ 客户端没有网络层。`NpcRoster.cpp` 的名称/坐标提示、候选模型和
  `10009` 回退只是临时实现，不是通用方案。

### 2.2 聊天与右侧 UI

- `config.pak` 和 `800config.pak` 的 `ui/main/chatmain.scp` 都有 50 个控件
  节点；根矩形分别为 640×480 和 800×600。实际加载版本与 549×590 客户区
  的计算仍须以 `FSChatMain` 为准。
- 原 `chatmain.scp` 已声明顶排频道按钮、底部按钮排、`LISTVIEWEX` 消息区、
  隐藏的输入条 `chatmain_barwnd`、`COMBOBOX` 和 `RICHEDIT`。当前实现未支持
  这些关键控件，却把源布局整体缩放，因此截图差异不是简单换皮可以解决的。
- `config/UI/main/fucnbtn_shortcut.scp` 声明 8 个快捷入口：串联活动、你画我猜、
  关系、阵营战排行、家族活动、跨服副本、活动链接、帮助。显示条件和排布还受
  原 Lua/C++ 控制，不能只把全部按钮叠在配置原点。
- 主界面还包含任务追踪等代码自绘区域，需要与静态 SCP 面板分开处理。

## 3. 方案取舍

采用方案 A：证据驱动的公共底座与三条垂直验收线。

- 不采用“先修截图、网络后置”：会重复实现聊天控件并继续扩大 NPC 硬编码。
- 不采用“先完成全部网络再做 UI”：范围过大，现有视觉问题长期无法验收。
- 协议回放先于实网，使解密、消息路由、对象生命周期和 UI 可以离线重复验证；
  实网接入不复用另一套场景或 UI 数据路径。

## 4. 总体架构

### 4.1 统一消息来源

设置统一的解码消息接口，由“抓包回放源”和“实网会话源”实现。两者输出同一
领域事件：聊天消息、对象创建/更新/删除以及后续面板响应。场景和 UI 不感知
消息来自回放还是服务器。

回放和实网共用消息路由、对象仓库、聊天模型与面板管理器。实网登录只在回放
链路通过后启用。账号、密码、会话值和 MAC 不进入日志或提交的测试产物。

### 4.2 NPC 静态定义与动态实例分离

静态表提供 NPCID、地图、格子、分类、对话和传送信息；网络对象提供当前对象
ID、shape、位置、方向与可见性。生产路径移除测试 NPC 入口、模糊名称/坐标
匹配、候选模型猜测和 `10009` 通用回退。无法确认的对象记录原因并跳过。

NPC 帧头偏移和实体位置在统一绘制锚点中处理，不逐 NPC 修改坐标。动画继续按
视口懒加载，单个资源失败不阻断地图。

### 4.3 SCP 公共控件

补齐 `LISTVIEWEX`、`RICHEDIT`、`COMBOBOX`、`SCROLL` 和相应消息分发，供主
聊天栏、独立聊天窗及其他面板共用。`FSChatMain` 的窗口尺寸、皮肤平铺、文本
布局与输入条状态按二进制证据实现，废止当前 640×500 -> 549×590 的整体缩放。

### 4.4 面板注册表

使用“按钮控件/消息 -> SCP/Lua 面板或代码面板”的注册表，统一处理面板创建、
关闭、切换、滚动和数据空状态。右侧快捷按钮的显示与位置由原配置/Lua 决定；
任务追踪等代码自绘区域单独实现。

### 4.5 只读动态分析

参照客户端只进行用户提供的运行实例上的只读观察。用户配合打开/关闭聊天窗或
点击指定按钮，分析侧负责截图和证据记录；不启动、关闭或修改参照游戏进程，
不修改旧版资源目录。

## 5. 数据流与交互

### 5.1 NPC

```text
回放/实网 -> 消息解码 -> 对象仓库 -> 地图可见对象
         -> shape 直接解析 npc.pak -> 懒加载动画
         -> 统一锚点/深度排序 -> 模型、方向与名字
```

`0x301e/0x301f/0x30a0/0x300d` 的具体职责和字段必须先验证。对象 ID 用于更新
与删除，不能用显示名称充当实例主键。静态 CSV 只补充静态元数据。

### 5.2 聊天

```text
0x303f -> 频道/发送者/富文本与物品链接/正文
       -> 共享聊天模型 -> 频道过滤/换行/滚动
       -> 主聊天栏或 FSChatMain 独立窗口
```

底部输入条支持真实编辑、频道选择和发送消息结构。回放模式不伪造发送成功；
实网阶段才启用 `0x4050` 发送。频道按钮、底部按钮、皮肤和输入区均按原版
坐标与状态绘制。

### 5.3 右侧按钮与面板

按钮事件进入面板管理器并加载真实 SCP/Lua。回放有数据时显示录制内容；无数据
时显示真实空面板。排行、家族、活动等请求协议在对应面板实施时逐条增加，不
以假数据填充。任务追踪未收到任务数据时为空。

原始抓包和真实聊天截图只放 `.rea/`。提交的协议样本只保留必要字段，并脱敏
账号、会话值与隐私文本。未知命令、字段和控件明确报告未支持。

## 6. 实施顺序

1. 固定当前未提交基线和测试证据；确认 `FSChatMain` SCP 版本、尺寸、皮肤、
   消息布局和 NPC 锚点。
2. 建立 C++ 协议回放边界与黄金样本，接对象/聊天消息路由。
3. 建动态 NPC 仓库，删除测试 NPC 生产入口和模型回退，修统一绘制锚点。
4. 实现公共 SCP 控件，恢复主聊天栏与独立聊天窗。
5. 建右侧按钮覆盖清单，逐个接通真实面板和通用交互。
6. 回放全部通过后接实网登录、进入世界、对象同步与聊天发送。

## 7. 错误处理

- 单个 NPC、动画或图片失败：记录逻辑路径并跳过，不阻断本地地图。
- 畸形回放协议：明确令对应样本失败，不截断后假装成功。
- 实网畸形消息或连接失败：隔离错误或断开对应会话，本地探索仍可用。
- 未知按钮、控件、消息和字段：输出可定位诊断，不静默成功。
- 网络不可用：不影响既有地图、动画和本地 UI 回归。

## 8. 验证与完成标准

1. 现有 CTest、真实资源测试和窗口烟测通过；新增协议黄金样本、NPC 生命周期、
   聊天布局/过滤/滚动和按钮面板测试。
2. 启动真实 `dhsh_client.exe` 完成端到端验收，不只验证导入或编译。
3. 当前 6 个可见 NPC 的名称、模型、位置、方向与参照一致；无 `10009` 测试
   NPC，无整体右下偏移。
4. 原版与复刻独立聊天窗同尺寸对拍；频道、滚动、输入条和开关窗操作正确。
5. 每个右侧按钮都有控件、消息和目标面板映射，并实际点击验证打开/关闭及
   通用交互；未接业务协议的面板保持真实空状态。
6. 最后进行实网登录、聊天收发和 NPC 移动/刷新验收。实网问题不得通过修改
   回放样本掩盖。

## 9. 安全与版本约束

- `D:\software\dhsh` 只读，所有输出写入本仓库。
- 不运行旧版游戏或保护组件；不加载原 EXE/保护 DLL 作为复刻运行时。
- 不启动、关闭或修改 `D:\software\dhsh2` 的参照进程。
- 保留当前未提交工作，不自行提交或推送。
- 工具优先复用 `tools/dhsh`、`tools/art_pipeline`、现有 SCP/APG/NZ 解析器和
  `tools/kimi_msg_*`；只逆向尚缺失的语义。
