## 2. 帧格式（线上与内存一致）

```
[u16le 长度（不含本字段，明文）][加密载荷]
```

载荷解密后：

```
+0x00  u16   命令号（s2c 为 0x30xx，c2s 为 0x40xx；0x2xxx/0x2500 为内部命令）
+0x02  ...   载荷字段（cmd < 0x2501 时头部 16B，否则 20B）
+0x0e  u32   密钥位置种子（加密时写入，= 出站序号 DAT_00ad0f0c 递增 2）
```

## 3. s2c 解密（静态表，逐帧自包含）

解密函数：旧构建 `FUN_00819610` / 新构建 `0x819750`（字节级一致）。
密钥表：`DAT_00a43eb8`，0x1000 字节，**磁盘文件偏移 0x643eb8**（.rdata identity）。

```
pos = (u32(载荷+0x0e) - 0x0d) mod 0x1000
逐字节 i ∈ [0, len)，跳过 i ∈ [0x0e, 0x12]（含 0x12，共 5 字节）：
    s = pos & 7
    b = ror8(b, s)                  # (b >> s) | (b << (8-s))
    b = KEY[pos] ^ b
    pos = (pos+1) mod 0x1000
然后前 min(len,16) 字节：b = ror8(b, 3)
```

调用点：分发器在 `flag != 0 && DAT_00ae1374 != 0` 时对 `msg+2, len-2` 原地解密。
实现：`tools/kimi_msg_crypto.py`（实测 180s 抓包 334KB → 1031 帧明文）。

## 4. c2s 加密（Blowfish 登录帧 + RC4 会话帧，已完全离线可解）

出站链：`FUN_007a0f60`（新构建 `0x7a1080`，出站预处理：写序号 @+0x10、
逐命令标志位）→ 拷入暂存 `DAT_00ac0f08`（**此步把指针引用的文本序列化进帧**，
头部字段重排）→ 加密 → `FUN_007a0730` 发送。

**加密分两种，由 `DAT_00ae145c` 首帧标志切换（cmd 0x4004 经过预处理器时复位）：**

1. **首帧 = 登录帧 0x4004**（长度 0x6f）：`FUN_00819850(buf,len,2)` →
   `FUN_00819760` 逐 8 字节 `FUN_00819160` = **Blowfish 加密**（自定义变体：
   F(x)=((S1[x>>8&0xff]+S0[x&0xff])^S2[x>>16&0xff])+S3[x>>24]，密钥编排
   `FUN_00819510`：P[j]^=(k[4j+3]|k[4j+2]<<8|k[4j+1]<<16)<<8 循环，链式填 P+S）。
   密钥 = 静态主密钥字符串（103B，磁盘 `0x644eb8`），P 初值 `0x643e70`、
   S 盒初值 `0x643eb8`（π 小数，与 s2c 表同一块）。**全静态 → 离线可解。**
   末尾不足 8B 时 CTS 式交叠加密（`FUN_008197e0` 为对应解密）。
2. **后续所有帧**：`FUN_00934e30` = **标准 RC4**（状态 `DAT_00ad0f10`，跨帧连续），
   KSA（`FUN_009351f0` 标准）密钥 = **93B 凭据块 + MD5大写hex(凭据块)32B = 125B**。
   凭据块：+0 账号、+0x33 密码、+0x47 u32 会话值（`DAT_00ae131c`，来自网关重定向
   命令参数）、+0x4b MAC 字符串（"%02x:..: %02x"）。**登录帧明文自带整个凭据块
   → 抓到登录帧即可派生全部密钥，无需任何内存读取。**
   加密后追加 4 字节尾 = MD5大写hex(密文[:min(L-4,256)])[0:4] 的 ASCII；
   长度字段含尾。

线上帧布局（c2s）：`[u16le L(明文)][L-4 密文][4B MD5尾]`，登录帧无尾。
密文解密后：`[u16 cmd][2B][2B][u32][u32][u32 序号 @+0x0e][载荷 @+0x12]`。
序号 = `DAT_00ad0f0c` 逐帧 +2，高字节含状态标志位（0x02000000 等，见预处理器
`| 0x4000000` / `& 0xfdffffff` 分支）——比较低 24 位需掩码。

**实证（21:09 登录抓包 `.rea/sniff_login1_*`）**：62/62 帧全部解出：
登录帧 cmd=0x4004、账号/密码/会话/MAC 与进程内存逐字节一致；
0x40d0×4 参数 7/2/1/3 与 `FUN_00410810` 的四个 `FUN_007a1b40(0x40d0,…)` 调用
一一对应；0x4210 反外挂帧内嵌会话值 `0x2bd1dd8e`；聊天帧还原出测试消息
"t66est123123"（频道 5=世界）；全部 RC4 帧 MD5 尾校验通过。

明文 hook 点（新构建地址，调试用）：

| 挂钩点 | 地址 | 内容 |
|---|---|---|
| `0x7a1080`（预处理器入口） | 消息含指针，文本不在帧内 | 固定头 + 相邻堆内存里的文本 |
| `0x934f70`（FUN_00934e30 加密入口） | **最终线上明文（文本已内联）** | `[len][cmd][序号][频道][…][4B校验][文本\0]` |

## 7. 未确定事项

- ~~序号种子哈希~~（已闭合 2026-10-23 晚）：反汇编确认算法移植正确
  （197 轮 rotl19 变异，种子 = 哈希缓冲区 +0x47 非对齐 u32 | 1）；
  **signed-char 语义是关键**（密钥编排按 `*(char*)` 读密钥字节，≥0x80 高位
  被 0xff 污染）。凭据 Blowfish 状态与活体转储 4168/4168 逐字节一致。
  序号字段低 25 位 = 计数器逐帧 +2，高位叠加状态标志（0x04000000/0x20000000）；
  登录帧自身的序号字段含未解释的高位差异（疑网关计数器延续），不影响解密。
- **登录期 s2c 暗区**：抓包流开头 ~4140 字节不可解。已排除：表密码、明文、
  RC4(会话密钥)、主密钥/凭据 Blowfish-ECB。客户端 s2c 解密器只有表密码
  （分发器无其他解密调用），推断为 **pktmon 丢失连接开头的包**导致首帧
  残缺 + RC4 类流密码位置未知。解决方案：改用 Frida 挂钩（分发器入口，
  零丢包且记录 flag）+ pktmon 双连接全流量抓包重录登录。
  另外 `DAT_00ab936c != 0` 时（换服过渡窗）分发器直接丢弃入站帧。
