## 2. 帧格式（线上与内存一致）

```
[u16le 长度（不含本字段，明文）][加密载荷]
```

载荷解密后：

```
+0x00  u16   命令号（s2c 为 0x30xx，c2s 为 0x40xx；0x2xxx/0x2500 为内部命令）
+0x02  ...   载荷字段（cmd < 0x2501 时头部 16B，否则 20B）
+0x0e  u32   密钥位置种子（加密时写入，= 出站序号 DAT_00ad0f0c 递增 2）
```

## 3. s2c 解密（静态表，逐帧自包含）

解密函数：旧构建 `FUN_00819610` / 新构建 `0x819750`（字节级一致）。
密钥表：`DAT_00a43eb8`，0x1000 字节，**磁盘文件偏移 0x643eb8**（.rdata identity）。

```
pos = (u32(载荷+0x0e) - 0x0d) mod 0x1000
逐字节 i ∈ [0, len)，跳过 i ∈ [0x0e, 0x12]（含 0x12，共 5 字节）：
    s = pos & 7
    b = ror8(b, s)                  # (b >> s) | (b << (8-s))
    b = KEY[pos] ^ b
    pos = (pos+1) mod 0x1000
然后前 min(len,16) 字节：b = ror8(b, 3)
```

调用点：分发器在 `flag != 0 && DAT_00ae1374 != 0` 时对 `msg+2, len-2` 原地解密。
实现：`tools/kimi_msg_crypto.py`（实测 180s 抓包 334KB → 1031 帧明文）。

## 4. c2s 加密（会话密钥，离线不可解）

出站链：`FUN_007a0f60`（新构建 `0x7a1080`，出站预处理：写序号 @+0x10、
逐命令标志位）→ 拷入暂存 `DAT_00ac0f08` → `FUN_00934e30` 加密（会话密钥，
由 `FUN_00819850` 在登录期初始化，经 `FUN_00819510` 密钥编排混合静态表
0xa43e70/0xa43eb8）→ `FUN_008150a0` 追加 4 字节校验 → `FUN_007a0730` 发送。

**离线解 c2s 需要登录握手推导会话密钥（本次抓包从会话中途开始，无密钥）。**
明文改走 hook：0x7a1080 入口的 args[1] 即明文消息。
